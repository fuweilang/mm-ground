# desktop-first-launch

客户下载正式客户端后，不删任何旧文件，也能在本机登录或注册并进入对话。浏览器登录仍走中台，账号只在中台。

## 问题

- 本机已修好的蓝圈、白屏，客户电脑仍会出现。官网安装包不一定包含 `60859f3`、`499b428`。
- 客户端在 `127.0.0.1`，未登录时把窗口跳到 `https://www.mmai.vip/login`。这个地址不是本机页面，Cookie 也种不上，WebView 会白屏。
- 客户不会处理 `~/.octop`。安装必须自己换掉过期运行时。
- 客户端要在本机完成注册，不能把用户赶去网页。

## 目标

- 官网包与已提交的客户端修复一致。
- 客户端登录与注册都停在本机，账号仍只在中台；两端用户管理都能看到。
- 点「企业控制台」用现有一次性票打开 Chrome，Chrome 不用再输密码。
- 安装自动替换过期运行时。失败要出字，不能无限蓝圈。

## 范围

- 客户端启动、本机登录/注册页、企业控制台跳转验收。
- 安装包里的运行时替换（已有 `499b428`，本 change 只确认进包并验收）。
- 验收标准写在 `specs/desktop-client/spec.md`。

## 非目标

- 把 Vue `/login` 搬进 Octop，或恢复 Octop 自己的用户表。客户端只对齐外观，不复制 Vue 应用代码。
- 客户端和 Chrome 共用 Cookie。
- 改 `~/.octop` 目录名，或迁到 `~/Library/Application Support`。
- 分仓、拆 Octop 大文件、藏 Octop 用户页、模型配置归中台、`pnpm dev` 合并、PeecAI。
- 本 change 不改中台登录/注册接口。注册走现有 `POST /console/api/auth/register`。现有接口不够时停下来问，不直接加字段。

- 换宝塔下载目录上的安装包：要用户点头。

## 风险

- `POST /console/api/auth/login` 只种 Cookie、响应体没有给客户端用的 token。本机完成登录必须靠现有交换，不能假设能读到 `www.mmai.vip` 的 Cookie。
- 注册成功后若 OIDC 交换失败，中台会留下账号、本机却没有会话；必须在这台机器上说清并允许重试，不能白屏。
- 登录或注册表单若再 `window.location` 到官网，白屏会回来。
- 同版本运行时不替换时，新包仍会跑旧运行时，蓝圈会复现。
